# 이펙트 렌더러 프로토타입 — Canvas2D vs WebGL

"이펙트를 더 화려하게 하려면 JS 말고 다른 걸 써야 하나?" 를 재어 보기 위한 비교판이다.
**게임 코드는 건드리지 않았다.** `proto/` 는 APK 에도 들어가지 않는다
(`android/app/build.gradle` 의 `syncWebAssets` 가 `index.html`, `css/`, `js/` 만 복사한다).

## 열어 보기

```bash
python3 -m http.server 8000      # 저장소 뿌리에서
# http://localhost:8000/proto/webgl-fx/
```

`file://` 로 직접 열어도 된다. 스페이스로 연출을 터뜨리고, 위쪽에서 종류·동시 개수·파티클 양을 바꾼다.

- **왼쪽**: 게임에 들어 있는 `js/render.js` 의 `drawCast` 를 그대로 부른다. 흉내가 아니라 진짜 그 코드다.
- **오른쪽**: `gl-fx.js` — 외부 라이브러리 없이 새로 쓴 WebGL 파티클 레이어.

## 잰 결과

번개 연출 기준, 각 캔버스의 그리기 호출 시간만 잰 값이다(평균 30프레임).
**소프트웨어 렌더링(SwiftShader)** 환경이라 실기기 GPU 에서는 둘 다 더 빠르지만,
*늘어나는 모양*은 그대로 본다.

| 동시 연출 | Canvas2D | WebGL | WebGL 파티클 수 |
|---|---|---|---|
| 1개 | 1.68 ms | 0.09 ms | 909 |
| 3개 | 4.03 ms | 0.11 ms | 2,749 |
| 6개 | 7.28 ms | 0.12 ms | 5,712 |
| 12개 | 12.17 ms | 0.14 ms | 11,397 |
| 12개 · 파티클 3배 | 18.77 ms | 0.31 ms | 34,197 |

요점은 배수가 아니라 **기울기**다. Canvas2D 는 연출 수에 정비례해 늘어나 12개에서
한 프레임 예산(16.7ms)을 넘긴다. WebGL 은 3만 개를 그려도 0.31ms 로 거의 눕는다.

지금 게임이 동시 필살 연출을 4개(전설 2개)로 묶어 둔 것도 이 기울기 때문이다.
WebGL 로 가면 그 제한 자체가 필요 없어진다.

## 보이는 차이

- Canvas2D 는 선과 도형이라 **또렷하고 그래픽적**이다. 겹칠수록 면이 넓어져 화면이 노랗게 덮인다.
- WebGL 은 파티클이라 **번지고 살아 있는 느낌**이다. 불길은 실제로 피어오르고,
  번개는 착탄점에서 불티가 튄다. 겹쳐도 빛이 더해질 뿐 뭉개지지 않는다.

취향 문제이기도 하다. 지금의 또렷한 그래픽 톤이 졸라맨 아트와 잘 맞는다고 볼 수도 있다.

## gl-fx.js 가 하는 일

- 파티클 하나당 float 9개만 GPU 로 올리고, **프레임당 그리기 호출 1번** (인스턴싱)
- 빛번짐은 셰이더에서 거리로 계산한다. `shadowBlur` 도, 텍스처 파일도 없다
- 파티클 상태는 `Float32Array` 하나. 매 프레임 객체를 만들지 않는다
- WebGL2 우선, 안 되면 WebGL1 + `ANGLE_instanced_arrays`, 그것도 없으면 `ok === false`
- 파일 하나 약 400줄, **의존성 0**. 오프라인 APK 와 100KB 크기를 그대로 지킨다

## 붙인다면

게임 전체를 옮기는 게 아니라 **이펙트 레이어만** 얹는 방식이다.

1. `index.html` 의 전투 캔버스 위에 WebGL 캔버스를 한 장 겹친다 (`pointer-events: none`)
2. `Battle.castFx()` 가 `this.fx.push(...)` 하는 자리에서 `glfx.emit(kind, x, y, …)` 도 부른다
3. 잘 나오는 종류부터 하나씩 옮기고, 옮긴 종류는 `drawCast` 의 `case` 에서 뺀다
4. `fx.ok === false` 면 지금 `drawCast` 가 그대로 돈다 — **되돌릴 구멍을 남겨 둔다**

`game.js` 와 `data.js` 는 손대지 않는다. `render.js` 도 `drawCast` 만 줄어든다.

## 남은 일

- 파티클 값 다듬기가 아직 프로토타입 수준이다. 한 개씩 터뜨릴 때는 잘 나오는데
  여러 개 겹칠 때의 밝기·수명 곡선은 더 만져야 한다
- 8종 중 `lightning`, `firestorm` 만 제대로 다듬었다. 나머지 6종은 얼개만 잡아 둔 상태다
- 화면 흔들림·섬광 같은 화면 단위 연출은 아직 Canvas2D 쪽에 남아 있다
- 실기기(특히 저가 안드로이드)에서의 WebGL 지원과 성능은 따로 확인해야 한다
